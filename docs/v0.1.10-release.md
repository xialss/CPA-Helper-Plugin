# v0.1.10 发布与验证

日期：2026-10-28。用户明确授权提交并发布已完成变更。当前状态：[v0.1.10](https://github.com/xialss/CPA-Helper-Plugin/releases/tag/v0.1.10) 已正式发布，Latest、非 draft/prerelease；双平台构建、正式产物核验和发布 DLL 回归完成。

## 内容

- 移除响应模型核验、原始响应/流式回调、请求摘要关联和响应暂存，以及管理接口、能力字段、界面和专用脚本。请求拦截前后均省略 Body。旧 `response_model_mismatch` 配置告警后忽略，旧验证接口返回 404。
- 增加可选的 per-Key Claude 单请求统一 5m/1h TTL；通过已验证的 CPA payload 规则控制已有缓存断点，唯一 `usage.handle` 生成 execution_id 关联的 `enforced_request` 元数据。需显式配置并适配 Helper 消费端，不能把它当 provider 实际 TTL 或第二份 token 账本。
- 仍针对 CPA v8.0.45 / C ABI 1 / RPC schema 7。策略兼容 0.1.0～0.1.9；目录兼容读取 0.1.9/v8.0.45 和 0.1.8/v8.0.32，启动不改写，显式同步以新 producer 发布下一修订。

## 部署与边界

升级前备份完整 state_dir 和 CPA 配置，停止 CPA 后替换对应平台库，保留状态再启动。旧核验配置可删除。TTL 缺省保持 CPA 行为；开启前按 [配置契约](claude-uniform-ttl.md)部署，Helper 接入按 [交接文档](claude-uniform-ttl-helper-handoff.md)执行。

不修改真实 VPS、CPA 或 Helper，不自动合并分支。不宣称已测 VPS 内存下降、Linux 动态加载、真实 provider/账单或 Helper 计费联调。发布后如需回滚，停止 CPA，恢复匹配的旧二进制和升级前状态备份；旧版会恢复已移除的核验实现与开销。
