# CPA v8.0.45 兼容升级实施计划

## 1. 执行约定

- 需求：[PRD](cpa-v8.0.45-prd.md)。执行状态的唯一任务入口：[tasks.md](tasks.md)。
- 2026-10-28 用户已授权执行；具体阶段和验证状态见任务清单。
- 延续单一目标策略：CPA v8.0.45 / C ABI 1 / RPC schema 7，不额外承诺 schema 6 Host 支持。
- 按阶段写入可审查的小批次修改；每阶段完成后检查 diff、测试及任务状态再进入依赖阶段。
- 不引入 CPA internal 包，不变更真实部署、凭据、远程仓库或用户已有未跟踪文件。
- 不以超时、空数据、旧 SDK 或未运行的测试代替目标结果；阻塞记录具体命令、错误和影响范围。

## 2. 决策记录

| 编号 | 决策 | 原因/约束 |
| --- | --- | --- |
| D-01 | 目标固定为 v8.0.45，schema 7 严格检查 | 符合仓库只支持单一已验证 CPA 目标的约定；不把同 schema 误当跨版本支持 |
| D-02 | 仅拦截后省略 Body | 拦截前 Body 仍用于无 RequestID 响应钩子的关联；配置可动态开启 |
| D-03 | 模型归属以 `host.auth.models` 的实际 ID 为准 | 消除重建 ID 与真实注册关系漂移；auth_index 不是唯一键 |
| D-04 | 元数据适配器按证据保留或缩减 | 新回调不提供完整状态；禁止为删除旧桥接而丢失停用/来源信息 |
| D-05 | 已知旧目录兼容读取，新目录显式同步后原子写入 | 避免版本常量变更导致永久冻结，也不在启动时暗改持久化来源信息 |
| D-06 | 新增显式刷新动作，普通同步保持只读 Host 注册状态 | 外部源刷新有网络与副作用，不应绑定页面打开或生成请求 |
| D-07 | 不新增 Usage、重放、executor 或 FrontendAuth 能力 | 上游增加这些字段不等于本插件需要消费；保持范围与数据面职责 |

D-04 已由固定源码及真实 v8.0.45 夹具确认：保留配置 ID 桥接以补足来源/停用元数据，
每条指纹、provider 和 index 必须精确匹配 Host 模型回调；移除逐凭据模型查询。
共享 index、文件/相对 auth-dir、停用和 keyless 均已通过真实浏览器夹具。
本轮交叉审查复现了停用 runtime-only AIStudio 条目只出现在 Host 模型集合且 `models: []` 的情形。
按 R-03 的窄例外排除这种无模型非所有者，不猜测来源/状态；保留完整 Host 集合双读及 UI 排除计数。
另经真实回归确认 v8.0.45 Chat handler 在插件错误分块后取消执行；测试按此终止契约检查，
真实截断在未被插件拒绝的流上单独验证。没有修改插件的错误形状或新增取消接口。
若必须改变策略指纹、管理协议版本或接受比 PRD 更宽的快照范围，先更新需求和风险分析，不能顺带实施。

## 3. 阶段与交付

### P0：固化范围与任务（规划阶段，已完成）

交付 PRD、计划和任务清单；记录实际兼容基线、13 个版本的影响、验收矩阵和已知环境风险。
仅新增规划文档，保留 `compatibility.md` 当前已验证记录；不改模块、版本或功能。

完成门槛：文档互链有效；所有已接受事项有任务和验收编号；未实施工作标记待办。

### P1：实施前契约与基线

1. 重读根/嵌套规则，检查 `git status --short` 和已有 diff，确认用户改动未覆盖。
2. 在 `docs/compatibility.md` 增加 v8.0.45 升级中记录，写明固定提交、C ABI 1 / schema 7、构建要求及迁移/回滚。
3. 用固定 tag 核查 SDK 类型、管理 callback 上下文、请求体能力字段、刷新响应及现有夹具。
4. 确定下一候选插件版本；若变化，列出 producer、schema、UI、文档等更新点。发布/打标签仍不在授权范围。
5. 保留一份隔离测试用的旧版有效目录状态，包含修订号与幂等收据，不使用生产状态。

完成门槛：目标契约先于 ABI 代码落盘，旧快照测试样本来源清楚，当前支持状态没有提前改为 verified。

### P2：SDK、构建与 schema 7

涉及：`go.mod`、`go.sum`、`internal/plugin/app.go`、`management.go`、相应测试及必要构建说明。

1. 使用 Go 模块工具固定 SDK v8.0.45，检查自动引入的 Go/dependency 变化，只保留必要 diff。
2. 准备 Go 1.26.10 和匹配架构的 C 编译器，记录实际版本；不依赖较低版本侥幸编译。
3. 注册及重配置要求 schema 7；capabilities 不再硬编码旧 schema 6。
4. 声明拦截后省略 Body；保留拦截前 Body。
5. 补 schema 拒绝无副作用、事务式重配置、能力字段及核验仍能关联请求的测试。

验证：相关 Go 单测、管理 capabilities 契约和动态库编译。验收：A-01～A-03。
依赖：P1。网络或工具链不可用时明确阻塞 SDK/构建任务，不把旧依赖视作替代。

### P3：目录快照兼容读取与新版本同步

涉及：`internal/catalog`、`internal/snapshot`、目录管理测试、catalog JSON schema。

1. 将运行时新写入目标校验与已知旧状态读取校验分开，固定支持的旧 producer/CPA 组合。
2. 对旧状态进行完整结构、关联和收据校验，不捕获所有 Compile 错误后重置。
3. 保留原始修订、时间、内容及幂等记录；只在内存中暴露必要的来源/重同步健康信息，不自动改写旧文件。
4. 允许第一次显式新目标同步按旧 revision + 1 写入，继续使用现有原子写路径。
5. 覆盖旧目录打开/服务、重新同步、重启、历史幂等重试、冲突、写失败和不确定持久化。
6. 覆盖未知版本/损坏状态仍冻结；新写入接口拒绝旧 envelope；策略 revision 不被目录更新改变。

验证：catalog/snapshot/management 表驱动测试及无密钥序列化检查。验收：A-08～A-10。
依赖：P1、P2；本阶段必须在新目录发布功能验收前完成。

### P4：Host 凭据模型数据与同步链路

涉及：插件管理/Host 适配、浏览器 `directory.js` 和 `app.js`、目录单测、真实 CPA 夹具。

1. 先捕获配置型、文件型、停用、keyless、相同 auth_index、相对路径等场景的官方回调结果。
2. 用实际 ID 对齐 `host.auth.models` 与官方元数据，不按 auth_index 去重；确定缺失元数据如何可靠补齐。
3. 按 R-03 确定最小管理响应；仅传输必要字段，持久化仍只含指纹、来源、provider、启用状态和公开模型。
4. 更新完整同步流程；移除逐凭据模型管理查询及已被替代的 ID 推导，仅保留经证据证明必要的元数据适配。
5. 加入标准化双读比较，覆盖凭据增删、状态变化和模型集合变化；包含被排除无模型条目的完整 Host 身份，失败不发布部分目录。
6. 保持 panel 打开自动同步、目录模型选择、过期策略选项展示和保存逻辑。
7. 回归前缀/别名/排除模型、共享归属、provider/category 限制和禁用凭据。

验证：Go Host/management 契约、JavaScript 目录测试和真实 callback fixture。
验收：A-04～A-07。依赖：P2、P3。
退出门槛：任何模型所有者无法验证准确来源或状态时明确失败；仅按 R-03 排除完整合法的 Host 独有无模型条目并显示计数，不以默认值隐藏目录缺陷。

### P5：显式刷新并同步 UI

涉及：`index.html`、`app.js`、相应 UI/管理路由 smoke。

1. 在既有样式内增加显式操作，与“同步 CPA 目录”区分。
2. 一次用户操作调用一次选定刷新路由，验证 HTTP 结果和 `ok`，成功后重新取得 Host 注册目录。
3. 区分上游刷新失败、刷新完成但同步失败、目录已发布并确认三种结果。
4. 检查重复点击、认证失败、页面初次加载、未保存编辑和网络错误，保留用户草稿和旧有效目录。

验证：路由请求/响应夹具及浏览器 smoke。验收：A-11、A-12。依赖：P4。
本阶段不得把刷新放进自动同步或请求热路径。

### P6：完整回归与隔离 CPA 验证

1. 在支持的工具链上运行格式、vet、全部 Go 测试、race 和目录测试。
2. 获取官方 CPA v8.0.45 平台产物，验证 release checksum 后解压到隔离测试目录。
3. 构建候选动态库，使用合成 Key、loopback mock upstream 和临时状态运行兼容 fixture。
4. 验证注册/重配置、管理认证/资源、callback、目录、策略、权重、流式、取消、重启、禁用再启用和回滚。
5. 以旧状态样本覆盖升级后重同步，确认无冻结、无 revision 重置、无秘密泄漏。
6. 运行浏览器 smoke，验证普通/显式同步、失败提示、规则选择、桌面/窄屏布局及草稿保留。
7. 对未运行的平台、真实 provider、外部管理员和终端 flush 故障注入分别说明，不扩充部署范围。

验收：A-01～A-15；依赖：P2～P5。任何 integration skip 必须单独记录，不能据此宣布支持。

### P7：文档和任务收尾

1. 对照验收矩阵逐项链接修改、测试名称和证据，检查没有未完成的必需任务。
2. 同步当前 README、compatibility、management-contract、testing、response-model-mismatch、JSON schema 及必要架构说明。
3. 保留历史版本验证记录；新支持记录只陈述实际验证平台、版本、checksum、日期和限制。
4. 检查 `git diff --check`、完整 diff 和状态，排除产物、缓存、临时状态、机器路径和无关格式化。
5. 将任务状态更新为已完成、失败或阻塞，给出简明交付说明；不自动提交或发布。

依赖：P6。必要验证未通过则不能将新版本标记为正式支持。

## 4. 验证命令与证据格式

实施命令如下；实际通过结果及未运行项见 [验收记录](cpa-v8.0.45-verification.md)：

```powershell
go version
go fmt ./...
go vet ./...
go test ./...
go test -race ./...
npm run test:directory
go build -buildmode=c-shared -o dist/cpa-helper-plugin.dll ./cmd/cpa-helper-plugin
# CPA_BINARY / CPA_PLUGIN_BINARY 必须指向隔离的、已校验版本产物。
go test -v ./integration -count=1 -timeout 90s
git diff --check
```

管理 smoke 以 [testing.md](testing.md) 当前约定和 P4/P5 新增契约为准；浏览器按现有脚本的实际参数运行。
若扩展真实夹具导致现有 timeout 不足，先根据新增场景的证据调整测试预算，不盲目增加超时以掩盖失败。

每项结果至少记录：任务 ID、命令/测试名、工具链/平台、目标 CPA 提交或产物校验、日期、
通过/失败/跳过/阻塞/未运行、错误摘要和覆盖范围。不将机器私有路径或原始凭据写入共享文档。

## 5. 恢复与偏离控制

- 升级前备份 CPA/插件二进制、配置和完整状态目录；规划文档不执行备份或部署。
- 回滚时停止 CPA，恢复配套二进制与备份状态；不直接重写 producer 字段伪造兼容。
- 修改某项设计时，先更新 PRD 对应 R/A 编号，再更新本计划与任务依赖；记录原因及证据。
- 未验证的元数据匹配、未知快照自动迁移、跨版本运行时支持和远程发布均不得临时加入范围。
- 阶段完成必须有对应证据；“下载了 SDK”“单测通过”“页面能打开”都不能替代 P6 完整验收。
