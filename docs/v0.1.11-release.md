# v0.1.11 发布与验证

日期：2026-10-29。用户已授权提交并发布。当前状态：[v0.1.11](https://github.com/xialss/CPA-Helper-Plugin/releases/tag/v0.1.11) 已正式发布，Latest、非 draft/prerelease；双平台构建、正式产物核验和发布 DLL 回归完成。

## 变更

- 修复 CPA v8.0.47 向插件发送宿主最大 schema 8 时，v0.1.10 因严格等于 7 而拒绝注册的问题。注册/热更新接受宿主 schema ≥7，没有上限白名单。
- 插件独立声明已实现的 `RPCSchemaVersion=7`；注册和 capabilities 一致，SDK 升级不会自动抬高协议门槛。C ABI 仍为 1。CPA 新增兼容能力时继续沿用契约；实际 ABI 或必需接口破坏性变化仍需显式处理。
- 保留请求体前后省略和已移除的响应核验状态，不启用 raw-body patch 或核验回调。TTL、权限、目录、调度及并发功能继续沿用现有契约。
- SDK 和目录 `cpa_version` 来源固定 v8.0.45，它们不是运行宿主版本门禁。版本变为 0.1.11，并保持 0.1.10 及更早合法策略/目录的读取与幂等收据兼容。

根因、已发布 v0.1.10 的真实失败复现和初始修复验证见 [协商修复记录](cpa-v8.0.47-schema-negotiation.md)。该历史 DLL 证据不能替代本次最终版本及正式产物验收。

## 升级与边界

备份完整状态目录和 CPA 配置，停止 CPA 后替换对应平台动态库，保留状态再启动。旧 v0.1.10 不能在 v8.0.47 注册，回滚前要恢复匹配的 Host、插件和升级前状态备份。

没有修改真实 VPS、CPA 或 Helper。Helper 的实际管理/TTL 接入仍按 [交接文档](claude-uniform-ttl-helper-handoff.md)进行，并接受 0.1.11 producer；本次不是跨服务计费验收。Linux 动态加载、VPS 内存采样和真实 provider/账单未在本机验证。未来 schema 模拟测试只保证协商规则，不将未知 Host 的破坏性变化伪称为已验证。
