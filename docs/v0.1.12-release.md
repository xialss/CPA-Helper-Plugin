# v0.1.12 审查、发布与验证

日期：2026-10-29。用户已授权一个 subagent 审查、修复问题，然后提交并发布新版本。当前阶段：审查及发布前验证通过，准备提交和发布；正式产物尚未生成。

## 变更与兼容

- 移除 Claude TTL 的请求状态、头改写、配置文件校验、usage 回调、执行元数据、管理接口和界面。模型权限、分组、列表过滤、目录同步/刷新、凭据子集调度、并发和生命周期保留；响应模型核验继续保持移除。
- 旧 YAML 显式告警后忽略；旧策略合法 TTL 字段只保留磁盘历史/精确幂等回执读取兼容，实际策略和 GET /policy 不携带，新增 TTL 策略写入拒绝。启动不改写状态，旧元数据不读、不写、不删。
- 精简运行状态三项显示：契约、模型目录修订、模型目录状态。目录来源使用官方 `X-CPA-VERSION` 显示当前运行版本；缺少响应头或目录 producer 时明确显示原因，保留错误详情。
- 版本升级为 0.1.12，显式保留 0.1.11 及更早合法策略、四种旧目录 producer 和原幂等回执兼容。C ABI 1、独立 schema 7、Host schema 最小 7 且无上限白名单；SDK 和目录契约来源仍固定 v8.0.45。

完整移除范围、CPA 配置清理和 Helper 交接见 [TTL 移除记录](claude-ttl-removal.md)。运行版本显示与目录契约来源的区别见 [兼容性](compatibility.md)。

## 升级与验证边界

升级前备份完整状态目录和 CPA 配置，停止 CPA 后替换对应平台动态库。管理员应移除历史 TTL 专用 CPA payload 规则及插件 claude_cache_ttl 配置块；插件不会编辑 CPA 文件。Helper 已接入时按 capability 缺失停用 TTL 编辑及元数据请求，保留历史计费记录；未接入则无需实现历史 TTL 交接。

若 Helper 对普通策略或目录的 plugin_version 使用白名单，应新增 0.1.12，继续使用 policy v1 和 cpa_version=v8.0.45；该固定字段不是 CPA 运行版本。Helper 工作区未修改。

二进制降级需恢复匹配插件、CPA 配置及升级前状态备份。无 CPA/Helper/VPS 部署改动；不将 Windows 验证视为 Linux 动态加载、VPS 内存实测或真实计费验收。
